# Stage 4 experimental memory adapter
CharacterMemory uses CharacterStorage for all reads and writes. Recall uses character/token overlap in Python; extraction accepts an async callable compatible with the original extractor. Only new memories with evidence IDs from the selected session are accepted. Importance maps to layers 1 (9–10), 2 (6–8), 3 (1–5). This mapping is provisional. No gateway wiring, vector search, automatic scheduling, supersede, reminder persistence, consolidation, RLS or real database testing. Exact deduplication is not concurrency-safe; recall loads all character memories. Do not deploy as a multi-character service. Tests: python -m unittest discover -s tests -q (18 passed); compileall passed.
